## 2026-09-17 — 撮影に使うブラウザは Chromium から替えない

**決定。** `pnpm exec playwright install chromium` で入れた Chromium 以外で撮らない。
軽い headless ブラウザ（`lightpanda-io/browser` など）に替えない。

**根拠。** README の「初回の較正結果（2026-09-16）」で、`layoutDiff` は
環境差 0.00% / 1px のずれ 0.12% と分離が取れている。この分離は
**Chromium で撮ったから出た数字**である。ブラウザを替えるとフォントの
ラスタライズとアンチエイリアスが変わり、較正をやり直すことになる。

速さのために測定の基準を動かすと、それ以前に取ったものと比べられなくなる。
ベンチの値打ちは試行どうしの比較にあるので、基準の固定を速さより優先する。

**覆る条件。** Chromium の撮影が全体の時間の主要な部分を占めると実測できたとき。
いまは実測していない（未検証）。替えるなら較正からやり直し、
README の較正結果の表も撮り直す。

## 2026-09-17 — LLM の経路を差し替えるものは入れない

**決定。** ゲートウェイ（`OmniRoute`・`experiential`・`freellmapi`・`gpt-load`）や
無料枠の口（`free-claude-code`）を計測系に入れない。

**根拠。** README の「課金経路」のとおり、ベンチは Claude Code が使っている認証を
そのまま使う Agent SDK で回っている。一次指標はターン数とトークン数で、
`total_cost_usd` は API 相当の推定値として併記している。
経路を替えるとモデルもトークンの数え方も変わり、**前後の試行が比較できなくなる**。

**覆る条件。** 「同じ UI を別のモデルで再現させたらターン数はどう変わるか」を
測ることにしたとき。そのときは経路の差し替えが目的そのものになる。
比較の単位を試行から「モデル × 試行」に広げる設計変更を伴う。

## 2026-09-17 — ブラウザ自動化の道具は要らない

**決定。** `camofox-browser`（検出回避）・`Scrapling`（抽出）・`katana`（巡回）を入れない。

**根拠。** ベンチがブラウザでやるのは 3 つだけである。

1. 自分で立てた Vite アプリ（`sandbox/`）を開く
2. スクリーンショットを 1 枚撮る
3. 参照画像と比べる

他人のサイトへ行かない（localhost）ので、見破られる相手がいない。
リンクをたどらない（1 画面）ので、巡回が要らない。
HTML を抜き出さない（画像として撮る）ので、構造の変化に強い抽出も関係ない。

**覆る条件。** 参照 UI を実サイトから直接撮ることにしたとき。
ただしその場合、参照の撮影条件（フォント・DPR）が固定できなくなるので、
`target.json` に撮影条件を書く今の設計と噛み合うかを先に確かめる。

## 2026-09-17 — ベンチの使い道：「削る」と主張するものを検証する

**気づき。** 2026-W38 の GitHub トレンド 307 件を見たところ、
**トークンやターンを削ると数字で主張するものが複数あった**。

| | 主張 |
| --- | --- |
| `mksglu/context-mode`（★22,630） | ツール出力をサンドボックスに逃がして 98% 削減 |
| `JuliusBrussee/caveman` | 原始人のように話して 65% 削減 |
| `rtk-ai/rtk`（Rust） | 開発コマンドで 60〜90% 削減 |
| `obra/superpowers`（★286,799） | 「実際に機能する」スキル基盤と方法論 |
| `affaan-m/ECC`（★257,769） | エージェントハーネスの性能最適化 |
| `cathrynlavery/diagram-design`（★39,929） | UI を作る側の 38 種の図のスキル |

どれも削減率を掲げているが、**第三者が測った数字は見当たらない**。
ui-bench は「参照 UI を再現するのに何ターン・何トークン要るか」を
同じ条件で繰り返し測れる装置なので、**入れる / 入れないで同じ target を回せば
主張の真偽が出る**。`campaign.ts` と `runs/` の蓄積がその土台になる。

**やるときの注意。** 変数を 1 つずつ動かす。スキルと部品（`shadcn-ui/ui` のような
コンポーネント集）を同時に足すと、どちらが効いたのか分からなくなる。
sandbox の部品構成はベンチの条件として固定する対象である。

**覆る条件。** 較正のノイズ下限が実参照で大きく出て、ターン数の差が
ノイズに埋もれると分かったとき。その場合は削減率の検証には別の指標が要る。
