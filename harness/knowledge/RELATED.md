# 関連研究との照合（2026-09-25）

ui-bench の指標を、同じ問い（ハーネスはどれだけ効くか）を扱う2本と照らした。

## HarnessTax（UC Berkeley / Arena, 2026-09-16）

- 何を測ったか: 3ハーネス（Claude Code / Codex CLI / Pi）× 7モデル、SWE-bench Lite 30問 + Terminal-Bench 2.0 30問、各3回
- 指標: 成功率（90試行中の合格率）、試行あたり費用（2026-09-01 の API 定価）、**解決あたり費用**（費用 ÷ 成功率）、
  ターン数（エージェントループの反復、上限100）、初回呼び出しのコンテキスト量
- 結論: 成功率はハーネスでほぼ変わらず、費用は最大約2倍（Claude Code は Pi の 2.0 倍、Codex の 1.6 倍）。
  **ターン数はほぼ同じ（15.4 vs 15.3）で、差は初回コンテキスト（10倍超のシステムプロンプトとツールスキーマ）から来る**

### ui-bench との対応

| HarnessTax | ui-bench | 差 |
| --- | --- | --- |
| 成功率 | 収束率（5段ゲート通過） | 合否が評価器でなく多段ゲート。ゲート自体が欠陥を持ち得る（H-1〜20） |
| 費用（API定価） | SDK 内蔵定価の推定 `$` | 同じ考え方。ただし `usage` は主ループのみだった → `modelUsage` に切替 |
| 解決あたり費用 | 未算出 | **追加すべき**。未収束の費用を分母に入れないと知見の効果を過大評価する |
| ターン（ループ反復） | 内側の往復 `num_turns` | ui-bench の「ターン」は外側（差分の突き返し）。内側往復が HarnessTax のターンに相当 |
| 初回コンテキスト | 知見の文字数（cold 21,502字） | 知見を足すと初回コンテキストが増える = HarnessTax の「税」を自分で払っている。費用差の一部はこれ |

示唆: 「知見で費用が下がる」を主張するなら、知見ぶんのコンテキスト増を差し引いた上で言う。
none が高いのは往復が2倍だからで、cold が安いのは往復が減るぶんが知見のコンテキスト増を上回るから、と書く。

## An Empirical Study of Harness Design for Coding Agents（arXiv 2609.20804）

- 何を測ったか: 固定ループのハーネスで、計画・行動空間・コンテキスト管理の3要素を振る。176構成 × 4モデル、SWE-Bench Verified + Terminal-Bench 2.1
- 指標: 成功率、タスクあたり平均費用、**軌跡長（ターン）**、ツール呼び出し数、平均入力トークン、ピークコンテキスト、コンテキスト溢れ率
- 結論: 各要素の効果はモデルとタスクに依存し、既定にできない。
  強いモデルでは計画が **編集後の過剰な検証を削る**（中央値 108→74 ターン、精度は不変）。
  弱いモデルの bash-only は「インターフェース外の出力」で軌跡が 71→15 ターンに短絡し、**課題の難しさと無関係な偽の失敗信号**を作る

### ui-bench との対応

| 論文 | ui-bench | 差 |
| --- | --- | --- |
| 過剰検証（強いモデル） | builder の自己検算（probe/scan 往復） | 内側往復 47〜106 の何割が検算か未計測。**往復の内訳（編集 / 撮影 / 計測）を数える**と対応づく |
| 偽の失敗信号（ハーネス制約） | H-15/17/18 の誤検知、H-19 のネットワーク断 | 同じ現象。論文は「モデルの無能ではなくハーネスの制約」と分けて報告している。ui-bench も `隔離` `ハーネス失敗` を分母から外す形に揃えた |
| 計画（構造化）の効果 | 変種B（構造抽出→骨格→精緻化） | 論文では計画は「弱いモデルを伸ばし、強いモデルの検証を削る」。ui-bench の B は効果なし = Opus は強いモデル側で、検証削減は cold 知見が先に果たしている可能性 |
| コンテキスト管理 | 未対応（1ターン内で SDK の autocompact 任せ） | 内側往復 100 超の試行は autocompact が入っている。ログに 74 回 'autocompact' 記録あり。効果は未評価 |

示唆: 次に足す計測は (1) 解決あたり費用、(2) 内側往復の内訳、(3) autocompact 発生回数。いずれも既存ログから取れる。
